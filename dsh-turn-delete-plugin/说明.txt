dsh-turn-delete-plugin —— DSH 插件：勾选删除会话轮次
================================================================
版本 1.0.0 ｜ 作者：DSH 会话内生成 ｜ 安装日期：2026-11-05

这个文件夹是一个完整的 DSH 插件包（bundle），实现"勾选某几轮对话并删除"。
删除是软删除：往会话日志里追加一条 surfaceOp=replace 的替换节点，把这几轮从
"模型能看到的历史"（surface）里遮蔽掉；磁盘上的原始事件一条不少。

----------------------------------------------------------------
一、每个文件是干嘛的
----------------------------------------------------------------
package.json        插件清单。声明包名 @local/dsh-turn-delete、导出哪些文件，
                    dsh.bundle.patch 指向 cordis.patch.yml，dsh.client 声明这是
                    带浏览器界面的插件。改包名要谨慎：DSH 用它做身份识别。
cordis.patch.yml    装载补丁。安装时被插进 profile 配置，插入一条
                    id=dsh-turn-delete 的插件行；删掉它插件就不加载。
index.js            宿主端（Node 侧）代码。注册 /turn-delete 命令：读会话日志，
                    按轮次算出要遮蔽的 surface 区间，追加替换节点。所有校验在
                    这里做，写坏了会抛错并且不改动任何已有事件。
client.js           浏览器端代码。会话头部右上角加"选择对话"入口；进入选择态后
                    每轮尾部出现复选框，头部变成"已选 N 轮 | 取消 | 删除 N 轮"；
                    点删除通过 ctx.remote.commands.execute 调 /turn-delete。
locale/en.json      英文显示名与描述（插件管理页读 meta 字段）。
locale/zh.json      中文显示名与描述。
locale/说明.txt      locale 目录的说明。
icon.svg            插件图标（插件管理页显示）。纯手绘 SVG，无外部资源。
说明.txt            本文件。

----------------------------------------------------------------
二、怎么用
----------------------------------------------------------------
1. 会话页面右上角（文件夹图标左边）点"选择对话"；
2. 弹出"选择要删除的轮次"面板，列出**这个会话的全部轮次**（来自宿主下的
   turnOutline 投影，不受"当前只加载了最近几轮"的限制），每条包含：
      第 N 轮   11-02 14:36        ← 轮次号 + 这一轮开始的时间（已加载的轮次才有）
      你问：<你当时问的原话，最多 3 行>
      它答：<这一轮回答的开头，最多 2 行>
   列表可上下滚动，勾选要删的几轮（可多选）—— 靠"原话 + 回答开头 + 时间"三样
   确认是哪一块。
3. 点"删除 N 轮"。成功时弹窗关闭，头部出现"已移除第 N 轮（模型此后看不到，
   日志原文保留）"，聊天记录里同时多一条 turn-delete 命令回执，作为永久记录。
   失败时弹窗**不会关**，底部用红字写明原因（例如"第 N 轮已经不在模型视野里了"）。
4. 点"取消"或按 Esc 退出。点弹窗外的空白处不再关闭弹窗，避免点偏一点就
   "什么都没发生"。

补充：进入选择态后，每一轮回答的底部也会出现一个 [ ] 第 N 轮 勾选框，
和弹窗里的勾选是同一份状态，两种点法都行（短会话用底部勾选更快）。

删除后在聊天里的样子：被删那一轮（你的提问 + 模型的回答）整轮**变浅**，
正文**加一条删除线**，并在该轮尾部出现一枚「已从上下文移除」小标签。
实现方式是按宿主每行自带的 data-chat-turn 属性写 CSS；如果将来宿主改掉这个
属性，删除线会退化成只剩那枚标签（功能不受影响）。

也可以直接在输入框敲命令：/turn-delete 2 或 /turn-delete 2,3 或 /turn-delete 5-7

----------------------------------------------------------------
三、删除之后到底发生了什么（必须知道）
----------------------------------------------------------------
A. 模型看不到它了 —— 这是真的删。下一次请求组装时，那几轮不在 messages 里；
   "上下文"标签页里能看到 用户消息/助手消息 少了几项。对被删内容里出现过的
   token，KV 缓存从第一个被遮蔽的 token 起失效，下一次请求会略慢略贵（一次性）。
B. 聊天记录里还在 —— 这是 DSH 的设计：聊天页展示的是"人看过什么"的原始流水，
   不是"模型看到什么"。插件 API 只能往聊天流里加行，不能删别人渲染的行，
   所以那一轮的文字不会从对话里消失。这正是软删除的定义：日志不动，视野变窄。
C. 原文仍在日志里 —— 用会话导出（dsh-session-log-export 的 ZIP）仍能看到全文。
   目前没有"撤销"按钮；要恢复只能把原文手动补回成一条新消息（二期可做）。

----------------------------------------------------------------
四、已知限制 / 技术要点
----------------------------------------------------------------
* 按"轮"删，不按"条"删。半轮（只删某一句话）需要另做区间选择。
* 只删"已结束"的轮次；正在生成的那一轮会在每轮尾部渲染时被跳过。
* surface 的第 0 个节点是系统提示词，禁止被轮次区间覆盖：宿主端会主动把它
  从区间里剔除，否则引擎拒绝（"node 0 holds the system prompt"）。
* v4 日志格式要求 system/message 带正数的 turn/step、字符串 id、role=system、
  content 数组和 source.kind='system-prompt'。空内容的 system 节点不会进入
  请求（"dormant"），所以它只占表面位置、不增加 token。
* 附件 blob 与派生索引不在首期清理范围内（删除只影响文本历史）。

----------------------------------------------------------------
五、出问题怎么办
----------------------------------------------------------------
* 头部没出现"选择对话"：刷新页面（Ctrl+F5）；再看插件管理页里
  "会话轮次删除"是否启用。
* 点删除后头部出现红字：把红字原文发给我。常见是"第 N 轮已经不在模型视野里了"
  （重复删除）或"第 N 轮还没结束"（等它生成完）。
* 改了 index.js 没生效：宿主端模块不会热更新，需要在插件管理里把
  include:dsh-turn-delete 停用再启用（本插件已验证可行），或重启 DSH。

----------------------------------------------------------------
六、测试时留下的会话（可随时归档，不要再往里聊）
----------------------------------------------------------------
* "故意发错的一轮消息" —— 早期版本写入过一条非法 system 节点（step=0），
  这个会话不能正常继续对话，建议在侧边栏归档。
* "临时测试：本轮待删除" —— 同上，早期版本测试残留。
* "验收测试：删除后继续对话" —— 一次误触发的长任务会话。
